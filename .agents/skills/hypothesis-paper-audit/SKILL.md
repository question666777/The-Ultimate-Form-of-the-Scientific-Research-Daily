# 假说论文自审计与自我提升（hypothesis-paper-audit）

> **本仓库范围（开源版）**：这里只包含**审计环节**——十五维评分框架（本文件）、确定性检查脚本（`scripts\check_paper.py`、`scripts\_verify_doi.py`）、运行日志模板（`assets\run-log-template.md`）与经验库（`lessons.md`）。
> 文中提到的**上游工具**（`insight_scan.py` 洞见引擎、`novelty_gate.py` 新颖性闸门、`insight-synthesis` 写作规范、选题/日报流水线）属于作者更完整的个人研究系统，**不在本仓库内**；它们对应的环节可依据本文描述自行实现或替换。审计脚本本身**零第三方依赖、纯标准库**，可直接跑通 `example\` 下的示例稿。

让论文具备「每审一遍就厚一层」的能力：审计 → 提炼经验 → 自改或提案 → 下轮更强。本技能只规定**怎么审计、怎么记录、什么能自己改、什么必须提案**，不替代写作技能（写作规范属于上游 `insight-synthesis` 环节）。

## 触发时机

**入口阈值（2026-10-21 起，先于一切）**：论文线**默认挂起**，不按周期审计。只有三条同时满足才启动本技能：

1. 洞见引擎候选带 **[硬] 标记且分数 ≥2.5**（`insight_scan.py` 的硬度分层：共享/中继须为分子或通路实体、度数 ≤4，疾病名与工具词不算硬桥接）；
2. 能写出一条**可证伪预测**（写明「若 X 成立则 Y 可观测，否则不成立」）；
3. `novelty_gate.py` 未判「抢先」。

未过阈值＝**不启动**：不写运行日志、不跑十五维、不开 D0。**零动作是合格状态**，不是欠账。2026-10-21 实测依据：跨域候选绝大多数只是疾病名/工具词共现，真正的硬桥接屈指可数且全部是已知机制的跨病种挪移；不达此阈值时连跑数期「无进展」审计，只是把流程当产出。

0. **选题立项 / 动笔前** —— 先过 **D0 投稿可行性前置判断**（gate，未过不得进入写作）
1. 论文定稿 / 投稿前 —— **强制**
2. 用户要求复盘、提升论文深度 / 连贯性 / 联系紧密性时
3. 论文发生实质性修改后

## 核心文件约定

```
<PROJECT_ROOT>\audit\
├── runs\YYYY-MM-DD.md       # 每次审计的复盘日志（追加不覆盖）
├── lessons.md               # 提炼后的持久经验库（唯一权威经验文件）
└── proposals\YYYY-MM-DD.md  # 需改写作规范 / 期刊策略 / 投稿包结构的提案
```

`lessons.md` 记录「怎么写才能更好」（能改变下一稿行为的教训），条目有 ID（P001 起递增）、来源日期、状态（`active` 生效中 / `fixed` 已固化到脚本或规范 / `retired` 不再适用）。上限 10 条 active；超出时最老一条转 fixed 或 retired，不允许堆积。新教训先查重再追加。

## D0 投稿可行性前置判断（动笔前 gate）

> **动笔前先过此关，未过不得进入写作。** 前十五维查「写得对不对」，D0 查「该不该写这个、投这个刊」——诊断再准，也救不回一个从一开始就选错形态的选题。
> **来源：2026-10-13 C004 被 Medical Hypotheses 直接拒稿**（纯文献整合、无一手数据/计算验证的假说，投该刊本属高概率 desk reject；约 724 行代码 + 一次投稿换一次 desk reject，成本须在动笔前算清）。

**前置硬阈值（2026-10-21 起，D0 的第一道闸）**：候选须带 `insight_scan.py` 的 **[硬]** 标记且 **分数 ≥2.5**，并附一条可证伪预测；`novelty_gate.py` 判「抢先」直接否决。达不到此阈值，**D0 不启动、不写日志**——纯共现（共享疾病名/工具词）一律不算候选，避免再用低质量选题消耗一次 desk reject。

**四要素评估**：

| 要素 | 要问什么 |
|---|---|
| ① 选题形态 | 假说 / 综述 / 观点 / 原始研究？目标刊收不收这种形态？ |
| ② 目标刊门槛 | 是否收纯假说？要不要一手数据？desk reject 率、审稿周期、费用？ |
| ③ 证据强度 | 作者能给出什么：一手数据 / 计算验证 / 仅文献整合？与②的门槛差多少？ |
| ④ 单次成本 | 时间、精力、机会成本——值不值这一次投入？ |

**四选一建议**（必须给出其一，不得含糊）：**投**（四要素匹配，进入写作）/ **换刊**（形态可行但刊选错）/ **降级形态**（如把纯假说改投综述、观点文）/ **不投**（严重不匹配，止损）。

**动笔前抢先核验（自动化，2026-10-16 起）**：第③要素「证据强度」不能只看「作者能给出什么」，还须先确认**这个假说有没有被别人抢发**。跑 `python tools\novelty_gate.py --source all --days 90`（对单条候选可指定 `--source scan|bridge|analogy`），把候选两侧概念丢进 Europe PMC + Crossref 近 90 天窗口核验：**抢先**（两侧均命中专有词）＝候选已被同期文献覆盖，D0 直接否决（换选题或换角度）；**疑似**（仅泛化词命中）＝人工判读；**未抢先**＝可进后续评估（仅代表窗口内无覆盖，不等于绝对新颖）。闸门退出码 2 ＝ 有抢先，须处理后方可动笔。

**纪律**：D0 未给出明确建议前，不得进入写作与后续十五维审计；结论写入运行日志首行；**「不投」是合法结论，不算失败**。

## 审计评分表（维度可扩展；当前 15 维，逐条给 通过/警告/失败/未观察 + 一句话证据）

> **维度数量不固定**：下表是当前版本，随工作推进按「扩展机制」增维；已增维在运行日志中记录。禁止为了凑数增维，只增「本轮工作真实暴露、且下一稿会因此改变行为」的维度。
>
> **第 8、9、11、12、13 维由确定性脚本自动判定**，不靠目测：
> `python scripts\check_paper.py`
> 退出码：0 通过 / 1 告警 / 2 失败。脚本结论可直接作为对应维度的证据填入运行日志；
> 脚本报失败时该维度即为「失败」，禁止用「目测正常」覆盖。
>
> **第 1、5、10、15 维脚本给启发式线索**（非判定），人工复核后定档。
> **第 14 维**用 `scripts\_verify_doi.py`（读稿件文献表，逐条 Crossref 核验）。

| 维度 | 检查要点 |
|---|---|
| 1. 原创增量 | 核心新机制（本文的「心磷脂桥」）是否真未被现有文献覆盖？有无未正面区分的直接竞争文献？**所有「首次 / 尚无 / no study」类断言一律标为「未核实优先权断言」，须作者确认**（借自 claesbackman/AI-research-feedback） |
| 2. 思想深度 | 机制链是否解释「为什么」（因果/机制），而非罗列现象？**机制链两个必答点：①「靠什么介质连接」②「介质如何作用于执行器」——只答①不答②即为深度缺口**。有无停留在描述层（P002 已固化于此） |
| 3. 联系紧密性 | 跨文献联系（C 条目）是否承载论证——是否满足 ≥2 条 F 支撑 + 一条可证伪预测？有无「凑数」联系？论证链条有无断点（A→B→C 中间缺环） |
| 4. 内容连贯性 | 章节间逻辑承接是否自然（每节结尾是否引出下一节）？有无跳跃/断裂？段落是否单一论点、首句是否主题句 |
| 5. 论点-证据对齐 | 每条结论性陈述能否指回具体 DOI（claim-evidence 矩阵）？有无无源断言？陈述的**方向/强度**是否与证据匹配（借自 K-Dense-AI/claude-scientific-writer） |
| 6. 可证伪性 | 每条预测是否有**明确证伪判据**（尤其决定性实验 P3）？有无不可证伪的模糊表述？ |
| 7. 竞争文献区分 | 是否正面区分 WFS1/ISR、单一通路+MRTX1133 类工作？区分是否具体到分子/机制环（而非泛泛「路线不同」） |
| 8. 格式合规（自动） | 跑 `check_paper.py`：六段结构齐备、摘要≤250、正文≤3000、图≤3、关键词≤6、文献≤50。退出码 2 即本维度失败 |
| 9. 引用完整性（自动） | 跑 `check_paper.py`：正文 [n] ↔ 文献表双向一致（无孤立条目/悬空引用）、DOI 格式合法、无重复 DOI。退出码 2 即本维度失败 |
| 10. 语言质量 | 清晰度、术语一致、无 AI 高频词堆砌、句子长短错落；脚本给启发式线索 |
| 11. 内部自洽（自动） | 跑 `check_paper.py`：摘要↔正文↔图注数值/术语一致；中英稿关键术语对齐。退出码 1 即本维度告警 |
| 12. 机制图-正文一致（自动） | 跑 `check_paper.py`：图注对每一环节的证据定性（实线=已有证据 / 虚线=本文推断）是否与正文对同一环节的定性一致？图注引用的机制要素是否都在正文出现？图 1 是否在正文被引用？ |
| 13. 投稿包合规与元数据卫生（自动） | 跑 `check_paper.py`：正文/标题页/封面信/Highlights 四件套是否齐备且数值自洽；docx 元数据是否已清理（creator 非 python-docx、无 thumbnail——**文档元数据职业卫生，不泄漏工具链痕迹，非「防 AI 识别」**）；AI 使用声明是否写明具体工具名与用途 |
| 14. 参考文献可解析性 | 所有 DOI 是否经权威源（Crossref）核验可解析？有无假引用、无法解析的预印本前缀？优先权断言所依赖的文献是否已核实存在？用 `_verify_doi.py` |
| 15. 外部说服力（敌对评审）（启发式） | 以「敌意审稿人」视角主动攻击，而非只查形式自洽。四条攻击向量：① **原创增量是否押在最弱证据环节**——核心新机制若恰恰建立在自己承认「未测/推断」的环节上，等于把卖点建在最软地基；② **跨语境收敛是否为硬拼合**——把两套独立语境（如脂质应激 vs 氧化还原）强行并到同一节点，桥接句若缺同源证据即为拼合；③ **有无便宜的决定性证伪实验**——若说不出一个低成本、能一刀切开的实验，评审会判其不可操作；④ **优先权断言是否与支撑强度相称**——强断言（首次/no study）若无对应强证据，即为过度主张。脚本给四条向量的命中线索（不计入退出码），人工复核后定档。**来源：2026-10-13 C004 被 Medical Hypotheses 直接拒稿后的根因复盘**（新意押在最弱证据、跨语境拼合、可检验性停在抽象层、独立作者无机构信号） |

> **敌对评审执行纪律（第 15 维）**：本维度不能靠「逐条打勾」通过。审计时必须**先扮演审稿人写下攻击**，再判断论文能否扛住：
> 1. 若核心新意建立在自己承认「未测」的环节上——**失败**（卖点=最软地基）
> 2. 若桥接句把两套独立语境并到一点却给不出同源证据——**警告**（拼合）
> 3. 若通篇说不出一个便宜且决定性的证伪实验——**警告**（不可操作）
> 4. 若存在强断言（首次/no study）而支撑强度不匹配——**失败**（过度主张）
>
> 一句话总判：**「这篇稿子，凭什么在一堆同类投稿里被留下？」** 答不出具体理由即为「未观察」而非「通过」。

## 可执行评论格式（五字段，借自 K-Dense peer-review）

任何「警告/失败」项，必须写成可执行评论，禁止只给结论：

- **位置**：章节 / 行号 / 段落
- **观察**：看到了什么（具体到原句）
- **证据或判据**：脚本退出码 / 文献 / 期刊规范
- **为何重要**：不修会怎样（评审会怎么想）
- **要求行动**：可直接照做的改法

## 扩展机制（可提升性的保证）

本技能是论文的元技能，自身也按以下规则进化，**升级本文件即生效**：

1. **新技能自动纳入检查**：每跑一次审计，先列 `.agents\skills\` 当前全部技能，与预检清单比对——新入库技能自动加入「技能可用性」检查
2. **论文级自定义检查项**：任何与本论文相关的技能可在其目录放 `audit.md` 声明专属检查项，self-audit 发现即执行
3. **评分表可增维**：新维度追加在现有维度之后（编号顺延），禁止删改既有维度编号；每次变更在运行日志中记录。**变更史**：D12–D14 于 2026-10-11 第二次审计新增（来源：本轮真实暴露的图-文证据分层不一致、投稿包元数据 AI 痕迹、DOI 未全量核验三处缺口）；D15 于 2026-10-13 新增（来源：C004 被 Medical Hypotheses 直接拒稿——旧 14 维只覆盖「形式自洽」，漏掉「外部说服力/能否在同类投稿中胜出」，故补一条正交的敌对评审维度）；D0（前置 gate，非评分维，编号前置）于 2026-10-13 新增（来源：同一拒稿复盘——有十五维事后诊断，却无动笔前「该不该投这个刊」的前置否决权，故在评分表之前加 D0 投稿可行性 gate）。
4. **方法论可持续吸收**：发现更好的审计/写作方法（来自新技能、文献或用户输入），以「借自 XX」标注来源后融入本文件

## 执行流程

1. **先跑确定性脚本**（不占上下文、结果客观）：
   ```
   python scripts\check_paper.py --json audit\last_check.json
   ```
   记录退出码；脚本发现的问题自动构成第 8、9、11 维结论，并把失败明细原文抄进运行日志。
2. **对照评分表逐项打分**，证据必须具体（文件名、数字、行号、退出码），禁止「一切正常」式空话；随后执行扩展机制发现的自定义检查项
3. **写运行日志**：按 `assets\run-log-template.md` 结构存到 `audit\runs\YYYY-MM-DD.md`
4. **提炼经验**：只把「可复用、下一稿能改变行为」的发现写入 `lessons.md`；一次性小插曲只留在运行日志
5. **分级处置**：
   - **可直接自改**（当日生效）：修论文笔误/术语不一致、修 `check_paper.py` 的 bug、更新 `lessons.md`
   - **必须提案**（写 `audit\proposals\YYYY-MM-DD.md`，等用户确认）：改写作规范、改期刊策略、改投稿包结构、改论文核心论证
   - 提案采用五字段格式（位置 → 观察 → 证据 → 为何重要 → 要求行动）
6. **汇报**：各维各一行（自动维标注退出码）+ 本轮新增维度（如有）+ 新增经验条数 + 提案数量

## 纪律

- 审计面向「论证质量」而非「重做研究」：不重判科学结论真假，只查论证是否成立、证据是否对齐、链条是否连贯
- **宁可漏记不可编造**：证据不足的维度标「未观察」，不打分
- **报告完整性 ≠ 质量**：格式缺项不直接换算成「论文好坏」的结论（借自 K-Dense peer-review）
- **不得臆测缺失内容**：用「未报告」而非脑补填补
- **「首次/尚无」类断言一律标为未核实优先权断言**，须作者确认后方可保留
- 自改后必须在运行日志里记录改了什么、为什么
- 扩展机制吸收的改动必须标注来源、可在下次运行日志中追溯
- **主动审查纪律**：每次审计不能只审当次改动，必须额外扫视论文整体健康——论证链条有没有薄弱环、竞争文献有没有新出现、经验库有没有膨胀
