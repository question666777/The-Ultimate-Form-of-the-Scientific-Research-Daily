# 运行自审计（self-audit）

让流水线具备「每次跑完都检讨自己、下次不再犯同样错误」的能力。本技能只规定**怎么审计、怎么记录、什么能自己改、什么必须提案**，不替代任何业务技能。

## 触发时机

1. 每日日报流水线收尾（清理完成后、最终汇报前）——**强制**
2. 用户要求复盘某次运行、检查流水线健康度、整理历史教训时

> **内向敌对自审（2026-10-13 新增）是每次审计的固定前段**，随本技能自动触发、不依赖用户提醒——「独立自主」的关键就在这里：审查必须**自发起**，不能等人指出来。

## 核心文件约定

```
i:\生物科学家\learning\
├── runs\YYYY-MM-DD.md      # 每次运行的复盘日志（一天一份，追加不覆盖）
├── lessons.md              # 提炼后的持久经验库（唯一权威经验文件）
├── memory\findings.md      # 结论记忆库（记「发现了什么」，第 12 维校验；契约见其 README.md）
└── proposals\YYYY-MM-DD.md # 需修改定时任务指令/AGENTS.md 红线的提案（任务改不了自己的指令）
```

`lessons.md` 与 `memory\findings.md` 分工：前者记「怎么做」（能改变行为的教训），后者记「发现了什么」（压缩过的领域结论 + 跨文献联系）。两者互不替代，审计时分别校验。

`lessons.md` 是跨运行的记忆：每条经验有 ID（L001 起递增）、来源日期、状态（`active` 生效中 / `fixed` 已固化到指令或代码 / `retired` 不再适用）。上限 10 条 active（与 lessons.md 头部声明一致，由 `check_closure_health.py` 读取核对）；超出时最老一条转 fixed（真固化了）或 retired（没用了），不允许堆积。新教训先查重再追加，禁止语义重复的条目并存。

## 内向敌对自审（每次审计的固定前段，2026-10-13 新增）

> **来源**：2026-10-13 用户指出「你缺少完全独立自主的审查机制」。本技能此前是一份**清单执行器**——只能找到「已经写进去要找的东西」。四处盲区全落在清单之外：维度计数漂移、忽略区残留、价值观矛盾、缺席的 gate。清单查得了「规定动作做完没有」，查不了「规定动作本身缺没缺」。
>
> **姿态**：掉头攻击自己。前十三维查「运行做得对不对」，本节查「本项目的规则/流程哪里自欺、哪里漏」。**审查必须自发起，不能等用户指出来。**

### 向量 C · 矛盾扫描（宣称的原则会不会互斥）

1. 列出项目**宣称的原则**：AGENTS.md 零（根本目标）、零·补（懒人模式）、五（红线），以及各技能 `纪律` 节。
2. 两两问一句：「这两条碰在同一件事上，会不会给出**相反**要求？」
3. 命中即写成矛盾对——2026-10-13 实测：`humanize_text.py` 六维去 AI 痕迹 与 `5_Declaration_of_Generative_AI.docx` 声明来源，一个在抹痕迹、一个在声明来源，方向打架（处置：改定位陈述，「去 AI 化」＝写作质量提升，非规避检测）。
4. 处置：改定位陈述（多数情况）或改规则；能自改就自改，改不动的写提案。

### 向量 D · 缺席审查（该有 gate 的环节有没有）

1. 沿流水线逐步走：扫描 → 选题 → 深挖 → 写作 → 发信 → 清理；再逐个规则章节走一遍。
2. 每一步问：「这一步在做**取舍/判断**——那这个取舍有没有 gate（检查点/否决权）？」
3. 命中即写成缺席项——2026-10-13 实测：有十五维事后诊断、有 D15 敌对评审，却**没有**动笔前「该不该投这个刊」的前置否决权（处置：补 `hypothesis-paper-audit` 的 D0 gate）。
4. 处置：补 gate，或写提案。

### 纪律

- **产出必须落纸**：运行日志「内向敌对自审」段写下本轮候选（矛盾对 / 缺席项）；**无发现也要写「无」**并附一句「为什么认为无」。
- **不许凑数**：为交差编造矛盾，比查不出更糟。
- **连续 3 期无发现 = 审查空转**：与「经验库只进不出」「批判环空转」同类——须换角度（换被审对象、换提问方式），否则本机制退化成仪式。
- 向量 C/D **只能人工，不脚本化**：它们问的是「清单缺了什么」，而任何脚本都只能检查清单里已有的条目。可自动化的两条（派生事实重算、忽略区扫描）已固化进第 14 维脚本。

## 扩展机制（可提升性的保证）

本技能是流水线的元技能，自身也按以下规则进化，**升级本文件即生效，无需改动定时任务指令**：

1. **新技能自动纳入检查**：每跑一次审计，先列出 `.agents\skills\` 当前全部技能，与预检清单比对——新入库的技能自动加入「技能可用性」检查，无需修改本文件
2. **技能自定义检查项**：任何技能可在自己目录放 `audit.md` 声明专属检查项（如 gget 声明「验证 API 返回结构与文档一致」），self-audit 发现即执行

## 执行流程

0. **内向敌对自审（人工，先做）**：按上文协议跑向量 C（矛盾扫描）与 D（缺席审查），候选写入运行日志「内向敌对自审」段。**这一步排在所有脚本之前**——它可能改变本轮要查什么。
1. **先跑确定性脚本**（不占上下文、结果客观）：
   ```
   python tools\check_skills.py --json tmp\audit_skills.json
   python tools\check_report_consistency.py --html HTML\<YYYY-MM-DD>.html --json tmp\audit_consistency.json
   python tools\check_retractions.py --html HTML\<YYYY-MM-DD>.html --out tmp\audit_retraction.json
   python tools\check_closure_health.py --json tmp\audit_closure.json
   python tools\memory.py check --json tmp\audit_memory.json
   python tools\check_engine_health.py --json tmp\audit_engine.json
   python tools\check_self_review.py --json tmp\audit_self_review.json
   ```
   记录七个退出码；脚本发现的问题自动构成第 4、9、10、11、12、13、14 维的结论，并把失败明细原文抄进运行日志。
   **第 4 维不得因脚本失败而跳过不跑**——2026-10-11 的失守正是「脚本报 2 → 打成告警搁置 → 之后干脆不跑」。
2. **对照评分表逐项打分**，证据必须具体（文件名、数字、错误信息），禁止「一切正常」式空话；随后执行扩展机制发现的自定义检查项
3. **写运行日志**：按 `assets\run-log-template.md` 结构存到 `learning\runs\YYYY-MM-DD.md`，第 15 维按「论文线阈值闸门」一行记录（默认挂起，不写论文侧审计日志）
4. **提炼经验**：只把「可复用、下次能改变行为」的发现写入 lessons.md；一次性小插曲只留在运行日志
5. **分级处置**：
   - **可直接自改**（当日生效）：修复 `tools\` 或技能 `scripts\` 里的脚本 bug、更新 lessons.md、补充技能 references 的易错点
   - **必须提案**（写 `learning\proposals\YYYY-MM-DD.md`，等用户确认）：修改定时任务指令、AGENTS.md 红线章节、接口冻结项（send_email.py 参数 / topic_state.json 字段 / config.ini 字段名）
   - 提案采用五段式（借自 peer-review）：**位置 → 观察 → 证据 → 为何重要 → 要求行动**（含可直接粘贴的改法）
6. **孵化新技能**：同一类问题或手工补救在运行日志中**累计出现 ≥3 次**，在 `proposals\` 起草一份新技能 SKILL.md（frontmatter 完整、遵循本库技能结构），标题前缀 `[新技能提案]`，等用户确认后入库
7. **汇报**：在流水线结尾汇报中附审计结果摘要（十六维各一行，脚本自动维标注退出码）+ 新增经验条数 + 提案数量 + **闭环健康一行**（active 条数 / 未状态化提案数）+ **记忆库一行**（结论条数 / 本期新增 / 待补标签）+ **引擎一行**（R1 回归 / Q 条数 / D2+ 占比 / 候选落库数）+ **自审独立性一行**（派生事实漂移数 / 忽略区残留数 / 本轮敌对自审候选数）
8. **主动瘦身**（2026-09-25 新增，强制）：审计时必须扫视项目整体健康，发现就清不等用户指出：
   - 经验库三区（active/fixed/retired）有无膨胀——check_closure_health.py 已自动检查
   - 有无死技能——**按分层判定**（2026-10-01 修订，配合储备层模式）：核心层技能一次未调用＝事故，需查兜底链是否被误触发；储备层零调用属正常，只有「连续多期零激活且与项目方向无关」才标记待淘汰候选；SKILL.md 缺失或目录为空＝失败（2026-10-01 实测 `analytical-method-validation` 曾是空目录）
   - 有无残留备份文件（.bak-*）和 tmp 垃圾——**已由 `check_self_review.py` R2 固化**（直接扫文件系统含 .gitignore 覆盖区；此前「手动检查」是盲的——两者都被 .gitignore 藏起来了，git status 看不见）
   - 有无已结案提案堆积在 proposals/ 根目录——已结案的全部移入 archive/
   - AGENTS.md 和 tools/README.md 是否与实际文件同步——**已由 `check_self_review.py` R1 固化**（派生事实重算：源头 → 声明点比对）

## 纪律

- 审计面向「流程」而非「内容」：不重新评判科学结论对错，只检查流程是否按约定执行
- 宁可漏记不可编造：证据不足的维度标「未观察」，不打分
- 自改后必须在运行日志里记录改了什么、为什么
- 扩展机制吸收的改动必须在下次运行日志中可被追溯（改了什么、来源是什么）
- **主动审查纪律**：每次审计不能只审当次运行，必须额外花1分钟主动扫视项目整体健康——经验库有没有膨胀、fixed区是不是堆满了细碎bug、主题池有没有僵尸、最近几次运行有没有重复性问题。发现问题当场处理，不能等用户指出来才改（第 11 维闭环健康已通过 `check_closure_health.py` 强制检查）
- **独立自主纪律**（2026-10-13 新增）：审查必须**自发起**——既不能等用户指出问题才审（L034），也不能只审「已写进清单的项」。每期固定跑内向敌对自审（向量 C/D，人工）＋ 第 14 维脚本（R1/R2，自动），专查**清单自身的盲区**：清单查得出「规定动作做完没有」，查不出「规定动作本身缺没缺」
