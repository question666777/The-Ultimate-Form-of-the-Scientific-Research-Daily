# self-audit 自定义检查项声明

> 按 self-audit 技能「扩展机制第 2 条」：本文件声明 self-audit 每次审计时必须额外执行的检查项。
> 本文件为 self-audit 自身声明（元技能自检），2026-09-22 新增。

## 声明项

### A. 确定性脚本必须先跑

每次审计**开始时**，必须先执行下列脚本，再开始逐维打分。脚本退出码是本轮审计的输入，不是可选项：

| 脚本 | 判定维度 | 退出码含义 |
|---|---|---|
| `tools\check_report_consistency.py` | 第 9 维（报告自洽性） | 0 通过 / 1 告警 / 2 失败 |
| `tools\check_retractions.py` | 第 10 维（撤稿状态） | 0 通过 / 1 发现撤稿或更正 / 2 参数错误 |
| `tools\check_closure_health.py` | 第 11 维（闭环健康） | 0 通过 / 1 active 超限或有假 fixed / 2 提案队列有无状态条目 |
| `tools\memory.py check` | 第 12 维（记忆库） | 0 通过 / 1 告警（超字数/缺标签） / 2 失败（格式/ID/重复 DOI） |
| `tools\check_engine_health.py` | 第 13 维（机制推理引擎） | 0 通过 / 1 告警 / 2 失败 |
| `tools\check_self_review.py` | 第 14 维（自审独立性） | 0 通过 / 1 告警（残留垃圾或 registry 待同步） / 2 失败（派生标识漂移） |

**纪律**：脚本报「失败」时，对应维度禁止打「通过」；脚本因环境问题无法运行（如断网）时，对应维度标「未观察」并写明原因，不得默认为通过。

### A2. 第 11 维的判定口径（2026-09-22 新增）

`check_closure_health.py` 的四项检查与对应维度结论：

| 检查 | 通过条件 | 不通过时 |
|---|---|---|
| A. active 条数 ≤ 上限 | 读 lessons.md 头部「active 上限 N 条」 | 超限 → 告警，须列出可固化/可 retired 的条目 |
| B. 无「假 fixed」 | `tools/*.py` 固化清单里行首声明的 Lxxx 与 active 集合无交集 | 有交集 → 告警，**必须当场转 fixed**（这是最隐蔽的积压） |
| C. 提案全部有状态 | 每份 `proposals/*.md` 开头 900 字符内有状态词 | 有无状态 → 失败 |
| D. 无滞留提案 | 无「>7 天且无状态」的文件 | 有 → 失败 |

**「假 fixed」的定义**：lessons.md 里 status=active，但该 Lxxx 已被 `tools/*.py` 头部
「固化清单」显式声明为已固化。出现即说明「代码改了但经验库没同步」，active 会永远降不下来。

### A3. 第 14 维的判定口径（2026-10-13 新增）

`check_self_review.py` 的两组检查与对应维度结论：

| 检查 | 通过条件 | 不通过时 |
|---|---|---|
| R1 派生事实重算 | 每条派生事实的声明点全部等于源头真值 | 漂移 → **失败**（文档与事实不符，硬伤）；源头读不出 / 声明点正则未命中 → 告警（registry 待同步） |
| R2 忽略区扫描 | tmp/ 空、无 *.bak-*、无 __pycache__ | 有残留 → 告警（该清未清，瘦身纪律未执行） |

**纪律**：第 14 维脚本与「内向敌对自审」协议（向量 C/D，人工）是一套——脚本只查**清单里已有的条目**，
「清单缺了什么」只能靠人工对抗姿态补上。R1 的声明点**不含历史运行日志**（改了反而是篡改历史）。

### B. 脚本自身健康度

每次审计额外确认：

1. 三个脚本是否仍能被当前 Python 解释器导入执行（无语法错误、无新增第三方依赖）
2. 脚本引用的外部 API（Crossref `/works/{doi}`、OpenAlex `/works/doi:`）是否仍返回预期字段
   —— 任一 API 字段改名会导致判定静默退化为 `unverifiable`，需在运行日志中记录
3. 若脚本连续 3 次运行均返回 `unverifiable` 占多数，视为脚本失效，须提案修复
4. **`check_closure_health.py` 的固化声明解析规则**：只认「行首 L### 后跟内容」。
   若某脚本改用别的写法声明固化（如只在函数 docstring 里提一句），该条会被漏检 ——
   新增脚本时按其头部「固化清单」块格式书写，并在下次审计时核对检出条数是否与预期一致

### C. 新技能自动纳管

按 SKILL.md「扩展机制第 1 条」，每次审计先列 `.agents\skills\` 全部技能与预检清单比对。
**技能清单与数量以现场枚举为准，本文件不复制名单**（L038：派生标识从数据派生，不靠手填；
分类覆盖与核心层缺位由 `tools\check_skills.py` 校验）。

新入库技能出现时自动纳入「技能可用性」检查，并在运行日志中记一条。
