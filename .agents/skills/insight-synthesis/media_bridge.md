# 物理介质桥接层（insight-synthesis v3）

> 本文件是对 SKILL.md 的补充，专管「把跨文献联系从主题词层钉到分子-物理层」。2026-10-11 新增，源于用户对 v2 产出「浅共现」的批评。

## 一、为什么 v2 不够

v2 的类型层能判方向、判冲突，但**判定「两条结论有关」仍靠共享实体/共现**。后果就是 C004 这类产物——

- 原 C004：「胰腺癌两条代谢路线（IRE1α-XBP1s 重编程脂代谢 / GNAS-BCAA 喂 NAD⁺ 维持线粒体融合），都收敛到『保住线粒体代谢适应』，所以线粒体动态与 NAD⁺ 是软肋。」

这句话方向对，但**任何读完两篇摘要的人都推得出**（两篇都明说"线粒体""代谢""NAD⁺"），替换成本为零。它不是洞见，是并置。

v3 的目标：让结论必须**押在具体分子、具体物理量、具体执行器和一个能自我翻案的对照**上——只有既读懂机制、又持有介质词典的人才能推出来。

## 二、三条铁律（介质层候选的额外硬门槛，违反即退回）

| 铁律 | 判据 | 反例（退回） |
|---|---|---|
| 1. 介质具体 | 两篇现象落到**同一物理实体**（一种脂质 / 一个氧化还原对 / 一个接触位点 / 一个离子梯度） | 「都涉及代谢」「都涉及线粒体」 |
| 2. 旋钮正交 | 两篇各动一个**正交的**调节旋钮，最后作用到**同一执行器** | 两篇动的是同一个旋钮（=同轴，退化为共现） |
| 3. 方向可测 + 自带证伪对照 | 预测给出**方向**（升/降/解耦），且附一条同时给「支持/反驳」两种归宿的对照 | 「会协同」「值得研究」 |

## 四、介质桥接三步

1. **落地**：把每条 F 的现象翻译成一个可测物理量（"重编程脂代谢"→ 膜脂/心磷脂不饱和度；"喂 NAD⁺"→ NAD⁺/NADH 比值）。
2. **找同一执行器**：两介质的执行器是否同一（如都指向 OPA1/嵴）。不同 → 不构成桥接。
3. **判正交**：两旋钮是否正交。正交 → 同一软肋的两个**独立**旋钮（硬联系，score ×1.5）；同轴 → 退化为共现（降权，等同 v2）。

## 五、验收样例：C004 → C004★（心磷脂桥接）

**落地三步：**
- F051（IRE1α-XBP1s→FASN/MUFA 重编程脂代谢）→ 物理量：**膜脂/心磷脂酰基链不饱和度**（旋钮 A：膜几何）。
- F108（GNAS→BCAA→TCA→天冬氨酸→NAD⁺→融合）→ 物理量：**NAD⁺/NADH**（旋钮 B：氧化还原）。
- 同一执行器：两者都作用于 **OPA1 介导的嵴/融合** → 桥接成立，且旋钮正交。

**C004★ 三条预测（带方向 + 证伪器）：**

- P1★（介质身份）：MRTX1133 耐药株的心磷脂酰基链不饱和度应**下降**，与嵴坍塌程度相关；补外源油酸应**部分恢复**嵴形态。
- P2★（正交旋钮同一执行器）：对 GNAS 共突变株（走 NAD⁺-融合）施加 MUFA 枯竭，应触发 IRE1α-XBP1s 上调——交换旋钮仍打同一个 OPA1。
- P3★（证伪器）：油酸**只能救耐药株嵴、救不了 NAD⁺ 耗竭的去融合** → "膜几何 × 氧化还原"是两个解耦旋钮，机制成立；油酸**两个都能救** → 主轴只是单一"膜脂稳态"，正交旋钮模型被削弱，机制被推翻。两种归宿都能判定，才是可证伪。

**对比：** v2 的 C004 说"两线都靠线粒体"（可替换）；C004★ 说"MRTX1133 耐药会让心磷脂不饱和链变少、进而崩塌 OPA1 嵴，而这种崩塌能被油酸单独救回却不救 NAD⁺ 耗竭的去融合"。后者中间每一步都可独立检验、可被一条实验推翻——这就是不可替换性。

## 六、打分影响

命中介质桥接（过铁律 1+2）的候选，在 v2 score 上 **×1.5**；只过铁律 1 或 2 的 **×1.0**；都不过的按 v2 原分。理由：不可替换性越高的结论越值钱，本层的分母大（替换成本高），应区别于"谁都能拼的共现"。

## 七、与 insight_scan.py 的关系

介质桥接已由 `reason_engine.py` 的 **R1** 脚本化（2026-10-11 P1，设计见同目录 `reason_engine.md`）：读 `tools/media.json` 介质词典，对库内结论两两配对，输出「同执行器 + 正交旋钮」的桥接候选，正交者 score ×1.5。**C004 回归测试已通过**——引擎独立复现 `F051 × F108` → 共同执行器 OPA1/嵴重塑、正交。

仍需人工把关的两处：**介质词典的扩充**，以及「**落地**」（把现象翻译成物理量）——R1 靠 `media.json` 的 `entities` 反查，词典没覆盖的介质仍需人读原文补。v2 候选仍由 `insight_scan.py` 产出，R1 对其做二次判定。
