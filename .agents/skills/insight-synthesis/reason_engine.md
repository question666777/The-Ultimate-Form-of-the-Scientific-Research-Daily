## 一、诊断：现有推理为什么「低级」

现有 `insight_scan.py` 的四类候选，本质都是**图上的模式匹配**：

| 候选类 | 本质 | 缺什么 |
|---|---|---|
| A 直接共现 | 两节点共享邻居 | 说不出「靠什么」 |
| B 二跳链 | 图上找长度 2 的路径 | 路径成立不等于机制成立，无介质、无条件 |
| C 标签对冲 | 标签集合的集合运算 | 标签是元数据，不是机制 |
| D 谓词冲突 | 同一主客体极性相反 | 只判「矛盾」，不问「矛盾指向什么缺失变量」 |

三个根因：

1. **无介质**——三元组只有 `(主体, 谓词, 客体)`，没有「通过什么」。深度就是介质：C004 之所以浅，正因它停在「都碰线粒体」，没落到「靠心磷脂不饱和度」。`media_bridge.md` 已诊断这一点，但把它留成脑力活，没让脚本接手。
2. **无条件**——谓词是全域定性。「A 激活 B」在肝脏 / 三天后 / 低剂量下可能反转。无条件约束 → 大量伪联系。
3. **无问题**——库只存「已知」（F），不存「未知」。推理只能数据驱动（找能连的），问不出「为什么」。**没有「问题」这个对象，就永远生不出解释。**

R1 解决根因 1，R3 缓解根因 2，Q 问题库解决根因 3。

## 二、数据模型升级

### 2.1 介质词典 `tools/media.json`（新建）

`media_bridge.md` 的第三节词典是 markdown 表格，脚本读不了。迁成结构化 JSON：

```json
{
  "_meta": {
    "purpose": "介质桥接器 R1 的知识资产：把两条结论的现象钉到同一物理实体",
    "maintenance": "新介质入词典须能写出 structure/executor/knob_a/knob_b 四要素，缺一不入；来源 DOI 写进 refs",
    "version": "2026-10-11a"
  },
  "media": {
    "cardiolipin": {
      "zh": "心磷脂",
      "structure": "线粒体内膜",
      "executor": "OPA1/嵴重塑",
      "knob_a": "酰基链不饱和度",
      "knob_b": "NAD+/NADH",
      "entities": ["心磷脂", "线粒体"],
      "refs": []
    }
  }
}
```

字段闭集（与 `media_bridge.md` 三铁律一一对应）：

| 字段 | 含义 | 对应铁律 |
|---|---|---|
| `structure` | 归属结构（膜 / 接触位点 / 复合体） | 铁律 1 介质具体 |
| `executor` | 共同执行器（两旋钮最终作用的对象） | 铁律 2 旋钮正交 |
| `knob_a` / `knob_b` | 两个正交调节旋钮 | 铁律 2 |
| `entities` | 该介质对应的 `entities.json` 规范名（反查用） | 接口 |
| `refs` | 支撑该介质条目的 DOI | 可追溯 |

**首批 7 条**直接迁移 `media_bridge.md` 第三节表格（心磷脂 / NAD⁺-NADH / MAM / 膜张力 / 泛素周转 / MHC-肽-TCR / 核糖体解码几何），不新增内容。**迁移后 `media.json` 为唯一真相源，`media_bridge.md` 第三节表格改为指向本文件**——避免双份真相（同项目「不建 index.json」原则）。扩充纪律沿用 `media_bridge.md`：宁少勿滥。

### 2.2 实体词典 `entities.json`：不动

介质**不塞进** `entities.json`。理由：实体的 `type` 是单一枚举值，而介质是「结构 × 执行器 × 两旋钮」的复合结构，塞进去会把条目撑爆，且介质与实体是多对多。故新建独立文件，用 `media.entities` 做外键回指。`entities.json` 保持单一职责。

### 2.3 介质关联：落地锚定（`media.json` 的 `anchors`）

**不采用**在 findings.md 三元组行加后缀的方案——`insight_scan.py` 的 `TRIPLE_ITEM` 正则会因后缀而丢弃该边（P1 实测）。介质关联放在 `media.json` 的 `anchors` 字段：

```json
"cardiolipin": { ..., "entities": ["心磷脂"], "anchors": ["F051"] }
```

R1 关联判定 = **实体命中（`entities`，只放直接物理量）∪ 显式锚定（`anchors`）**。

**为什么需要 anchors**：`cardiolipin` 的直接物理量是「心磷脂」，但 F051 原文只写「脂代谢」——把「重编程脂代谢」翻译成「膜脂不饱和度」是**落地**，属知识动作，字符串匹配做不到。若把泛词「脂代谢」塞进 `entities`，任何提脂代谢的结论（如 F054 糖尿病糖脂代谢）都会被误拉进来——这正是 P2 实测的误报。故：`entities` 只放直接物理量，需落地的用 `anchors` 显式锚定。

**纪律**：`anchors` 是人工维护的落地表，每条须能写出「现象 → 物理量」的翻译依据（写进介质条目或 refs）。宁缺毋滥。

## 三、五类推理（引擎核心）

新增 `tools/reason_engine.py`，标准库实现，读 `findings.md` + `entities.json` + `media.json`，输出五类推理候选。

### R1 介质桥接器（Mediator Bridge）— 把 `media_bridge.md` 三步脚本化

**输入**：两条 F（A、B）及其三元组边。
**算法**（对应 `media_bridge.md` 第四节三步）：

```
step1 落地：对 A、B 的每条边，用 media.entities 反查介质
       → A_media = {m | m.entities ∩ entities(A) ≠ ∅}
step2 同执行器：对 A_media × B_media 的每对 (ma, mb)
       若 ma.executor == mb.executor → 候选桥接
step3 判正交：knobs(ma) vs knobs(mb)
       两对 knob 完全不同 → 正交 → score ×1.5（硬联系）
       有交集 → 同轴 → 降权 ×1.0（退化为共现，等同 v2）
```

**输出**：`A × B ｜ 介质对(ma,mb) ｜ 共同执行器 ｜ 正交判定 ｜ score`
**验收样例**：喂 F051（IRE1α-XBP1s→脂代谢）与 F108（GNAS→BCAA→NAD⁺），应输出 `共同执行器=OPA1/嵴重塑 ｜ 正交=是 ｜ 介质对=(cardiolipin, nad_redox)` ——即 C004★。**这是回归测试的判据（见第六节）。**

**与 `insight_scan.py` 的关系**：R1 不替代 v2 候选，而是**对 v2 的 A/B 类高分候选做二次判定**——v2 负责召回「值得看的配对」，R1 负责把其中命中介质桥接的挑出来并加深度分。

### R2 缺口检测器（Gap Detector）— ✅ 已实现（2026-10-11）

**输入**：库内全部三元组边。
**判据**（任一命中即报）：

```
① 层级跳跃：一条边两端 role 跨 ≥3 级 → 报「中间缺中介」
   role 序：molecular < process < cellular < tissue < organism < disease
   （intervention / other 不在轴上，一律跳过）
② 时间尺度错配：需人工标注的 condition 字段（秒级事件直连天级表型）——本库暂无，未实现
③ 度=1 的孤立枢纽：某实体在边图上度=1，但它 type=process 且被 ≥2 条结论正文提及
   → 提示「该过程可能被系统性低估，值得补检」
```

**输出**：`缺口位置 ｜ 缺失的中间层级 ｜ 建议补检的实体类型`
**价值**：这是「开放发现」的结构化版本——不问「哪些能连」，问「哪里本该有连接却没有」。

**实测收紧（P3，2026-10-11）**：R2 ① 初版按「跨 >1 级」实现，跑出 38 条，绝大多数是噪音。逐条核验后定下三道闸门：

1. **层级差 ≥3**（不是 >1）：`molecular → cellular` 这类差 2 级的直连是常规机制声明（TCR 调控 T 细胞、组蛋白调控 T 细胞），不是缺口；只有跨 ≥3 级（如 molecular → disease）才算「跳过整个中介带」。
2. **谓词须为机制型** `CAUSAL_PREDS = {ACTIVATES, INHIBITS, CAUSES, REGULATES}`：`TREATS/INDICATES/ASSOCIATED/TARGETS` 是治疗/诊断/标签关系，本身不是「谁把两端接起来」的机制断言，纳入会把「抗体抑制病毒」「A 标志 B」误报成缺口。
3. **两端都须是跨文献实体**（各出现在 ≥2 篇结论的三元组里）：这是最关键的一条。本库每条 F 是一篇自足论文，单篇自己讲清的直连（F058 吲哚→空肠弯曲菌已在该篇说明呼吸抑制）是**同篇自给**，不是缺口。R2 要找的是「库里分属不同论文、却缺一条中介边」的**跨文献**缺口，与设计立意（跨文献联系）一致。

三道闸门把 38 → 3（F005 肿瘤↔T细胞、F014 肠道菌群↔寿命、F071 病毒↔植物免疫），人工复核后剔除 F071（合成生物学自给回路），落库 Q003、Q004 两条。

**已知局限**：本库三元组稀疏，一篇论文的完整机制往往没被拆成多跳边，故「结构缺口 ≠ 知识缺口」——R2 输出只能当**待复核的候选池**，不能自动判定「库里真缺这条知识」。② 时间尺度错配依赖 condition 标注，本库没有，暂不实现。

**③ 孤立枢纽不入 Q**：其输出是「该过程被低估、值得补检」，属元层面的**标注提示**，不满足 Q 的三种问题型（为什么 / 什么连接了 / 什么条件下）。故单列为**补检清单**（`render_hubs`），不写入「三、问题」区。实测产出 4 条：生长（5 篇提及）、疫情、纤维化、脂代谢（各 2 篇）——是「该去补三元组」的工作清单。

### R3 张力检测器（Tension Detector）— ✅ 已实现（2026-10-11）· D 类的语义升级

现有 D 类只判「同一主客体、极性相反」。R3 在其上加两层：

```
① 条件依赖张力：同一 (主体, 客体)，不同 condition 下方向相反
   → 不判为「矛盾」，而判为「指向一个缺失的条件变量」
   例：A 在肝脏促进 X、在肌肉抑制 X → 缺的是「组织特异共因子」
② 同主体反向分叉：同一主体指向两个客体，方向相反且两客体同 role
   → 提示「该主体受两个相反下游牵制，可能存在开关」
```

**输出**：`张力对 ｜ 张力类型 ｜ 建议补检的变量`
**与 D 类区别**：D 类输出「这里有冲突」（问题）；R3 输出「冲突指向什么缺失变量」（假说种子）。

### R4 反事实 / 瓶颈分析（Bottleneck）— ✅ 已实现（2026-10-11）

**输入**：类型层有向图（实体为点，机制型三元组为边）。
**算法**（图论，标准库可做）：

```
对每个中间节点 M（同时有机制型入边与出边）：
   paths_bypass(M) = 绕开 M 的 X→Y 替代路径数（迭代 DFS，深度 ≤4，防环）
   若 paths_bypass == 0  → M 是【瓶颈】（必经，潜在干预靶点）
   若 paths_bypass > 0   → M 是【冗余】（有备份，可能是耐药机制）
```

**输出**：`X --p→ M --p→ Y ｜ 瓶颈/冗余 ｜ 触发 F 对 ｜ 若为瓶颈则提示为候选靶点`
**价值**：瓶颈 = 可证伪的干预点（对应深度分级 D3）。耐药研究里「冗余路径」本身就是发现。

**实测收紧（P3，2026-10-11）**：初版照搬「两端 role 跨 ≥3 级 + 两端均跨文献」的 R2 闸门，20 条跨文献中间链里只剩 1 条，且是「溶瘤病毒→化疗→肿瘤微环境」这类干预型节点，质量差。逐条核验后改为**四道闸门**：

1. **仅机制型谓词** `CAUSAL_PREDS`——瓶颈问的是因果必经，`TREATS/TARGETS` 等标签/治疗边不算。
2. **两条边来自不同 F**——同篇自给的 X→M→Y 不是跨文献链，无发现价值（与 R2 同源）。
3. **M 须是机制节点**（role 在层级轴上，非 `intervention/other`）——瓶颈要找的是可干预的**机制枢纽**，而不是「化疗」这种本身就是干预的节点。这一条剔除了初版唯一的假阳性。
4. **终点 Y 须跨文献**（出现在 ≥2 篇结论的三元组里）——Y 是链要抵达的表型/疾病，须是库内被反复锚定的实体；这条滤掉了「T细胞→乳糜泻」这类单篇噪声端点（乳糜泻只出现 1 次）与「疫苗→抗体→RSV」这类平凡直连。

四道闸门把 20 → 8（全为瓶颈，0 冗余），人工复核后落库 Q005（PD-1/PD-L1→小胶质细胞→肥胖）、Q006（RNA剪接→STING→衰老）、Q007（溶酶体→线粒体自噬→寿命）三条最扎实的跨领域瓶颈，其余 5 条留作候选池。

**已知局限**：本库三元组稀疏，「结构瓶颈 ≠ 真实瓶颈」——两条边构成的 2 跳链里 M 天然是唯一中间点，故 `paths_bypass==0` 几乎是稀疏图的默认结果，0 冗余正说明「库内根本没记录旁路」。R4 输出只能当**待复核的候选池**，问的是「M 是否真的唯一通路、有无未被记录的旁路」，不能自动断言「M 是干预靶点」。真正有价值的冗余/耐药发现，要等库内边足够密、能同时记录 X→M→Y 与 X→M'→Y 两条平行路径时才会浮现。

### R5 跨层级同构对齐（Cross-level Analogy）— ✅ 已实现（2026-10-11）

**输入**：库内两跳机制链（`causal_chains`：X -p1→ M -p2→ Y，两条边均为机制型谓词、来自不同 F、M 为机制节点）。
**算法**：

```
把链抽象为 pattern = (p1, p2, roleX, roleM, roleY)（抹掉具体实体）
对库内所有链两两比对 pattern 同构（谓词序列 + role 序列都相同）
   同构且三节点实体完全不相交 → 提出「跨系统迁移假说」
   例：ER应激→膜改造→功能维持  ≅  线粒体应激→嵴改造→功能维持
```

**输出**：`链A ｜ 链B ｜ 同构模式 ｜ 迁移假说`
**注意**：这类最易产噪音，**必须**过「生成-批判」闭环（下节）与人工复核才可入库；同构但无具体介质/条件支撑的，一律退回。

**实测收紧（P3，2026-10-11）**：设计初稿的判据是「谓词序列相同**或** role 序列相同」——实测该「或」太松：库内 19 条两跳链里，仅按谓词序列分组就能把「疫苗→抗体→抑制 RSV」与「病毒→激活植物免疫→抑制生长」判成同构（都是 ACTIVATES·INHIBITS），纯属噪音。故收紧为**谓词序列与 role 序列都相同**（`require_same_role=True`）+ **三节点实体完全不相交**。实测 19 条链 → 2 个同模式组，两组内两链均共享实体（组蛋白/TCR 组共享「T细胞、乳糜泻」；疫苗组共享「疫苗、抗体」），被「实体不相交」闸门正确滤除 → **同构候选 0 对**。这如实反映「库内暂无真跨系统同构」，宁缺毋滥；待库内边增密（出现两套系统里同一机制模式且实体不重叠）时 R5 会自动点火。

### 生成-批判闭环（Generate-Critique Loop）— ✅ 已实现（2026-10-11）

**定位**：把 SKILL.md 第六节第 5 步「自我反驳」从脑力活变成可执行的确定性环。每条候选（R1 桥接 / R2 缺口 / R4 瓶颈 / R5 同构）在入库前自动过一遍。

**三类攻击**（对应「找反例 / 找边界条件 / 找什么情况下会崩」）：

```
反例     —— 库内与候选实体相关的谓词冲突（同一 (s,o) 方向相反）→ severity 2（高危）
边界条件 —— R3 张力涉及候选实体（同一主体一边促进一边抑制）→ severity 1（需人工）
断链点   —— 候选链的中介 M 可被绕行（bypass>0）→ severity 1（需人工）
```

**裁决**：有反例 = 高危；仅有边界条件/断链点 = 需人工；三类皆无 = 存活（**只代表自动环没抓到把柄，仍须过 `tools\novelty_gate.py` 的自动抢先核验 + 人工复核**）。

**实测（2026-10-11）**：库内谓词冲突 0 处、张力仅 GLP-1 一处（且不在候选池），故当前 12 条候选全部「存活」——不是逻辑空转，是库小而干净。用合成候选（含张力主体 GLP-1）验证：批判环正确命中 2 条「边界条件」。该回归已固化进 `check_engine_health.py` 第 H 项，防止批判逻辑静默失效。断链点分支因库内暂无 `bypass>0` 的链，尚未用真实数据触发。

## 四、问题库（Q 条目）

**根因 3 的解法**：给「未知」一个一等公民。`findings.md` 新增「三、问题」区。

格式（正则须同步 `memory.py` 与 `insight_scan.py`）：

```
- **[Q001]**（2026-10-11｜open｜触发：F051、F108）什么把 ER 应激与线粒体嵴连接起来？
  - 候选解释：C004★（心磷脂不饱和度，共同执行器 OPA1）
```

字段：

| 字段 | 规则 |
|---|---|
| ID | `Q` + 三位序号，同样由 `renumber` 派生，禁手填 |
| 日期 | 触发日 |
| 状态 | `open` / `explained`（已被某 C 回答）/ `falsified`（候选解释被推翻） |
| 触发 | 由哪几条 F 触发（R3 张力 / R2 缺口 / R4 冗余 自动产出） |
| 问题 | 一句话，必须是「为什么 / 什么连接了 / 什么条件下」三型之一 |
| 候选解释 | 指向 C 条目；`open` 时可为空 |

**自动触发规则**：R1/R3 每产出一条正交桥接或张力，**强制**生成一条对应 Q（除非已有同 F 集触发的 Q）。R2 ① 层级跳跃、R4 瓶颈/冗余亦产出 Q，但都须先过各自闸门，且输出只当**候选池**，人工复核后落库；R2 ③ 孤立枢纽不入 Q，单列补检清单。这样问题库随推理自动生长，假说生成 = 用库里的 F 去回答 Q。

**Q 型归属**：R4 瓶颈/冗余问的是「唯一中介还是存在旁路」，归入「什么连接了」型，措辞写成「什么把 X 与 Y 连接起来——M 是唯一中介，还是存在旁路？」；候选中介的 X→M→Y 链直接嵌进问题句，故 open 状态可无 `候选解释` 行（该行仍留给指向 C 的成熟解释）。

**当前 Q 库实测（2026-10-11）**：Q001（R1 触发，已由 C004 回答 → 标 `explained`）、Q002（R3 张力，open）、Q003/Q004（R2 缺口，人工复核后落库，open）、Q005/Q006/Q007（R4 瓶颈，人工复核后落库，open）。

## 五、深度分级（D0–D4，C 条目入库硬门槛）

给 C 条目加 `深度` 字段，**只允许 D2 及以上入库**：

| 级 | 定义 | 判据 | 例 |
|---|---|---|---|
| D0 | 描述型 | 「A 和 C 相关」 | 都碰线粒体 |
| D1 | 机制型 | 「A 通过 B 影响 C」 | 有中间环节但无介质 |
| **D2** | 桥接型 | 「A 通过 B 影响 C，**介质是 m**」 | C004★ 心磷脂桥 |
| **D3** | 瓶颈型 | 「B 必经，去掉则链断」 | R4 输出的瓶颈节点 |
| D4 | 颠覆型 | 跨层级迁移，改变对系统的理解 | R5 的高置信同构 |

判定自动化：D2 由 R1 命中（介质桥接）+ 三铁律全过判定；D3 由 R4 瓶颈判定；D4 由 R5 同构 + 自我反驳通过判定。D0/D1 由「不满足以上」推定。

**作用**：现有 8 条 C 中约半数停在 D0–D1，本门槛把它们标出并降级为「已知并置」，逼新入库条目往 D2+ 走。这是「低级联系」的硬性拦截。
