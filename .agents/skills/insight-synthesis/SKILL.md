# 洞见综合（insight-synthesis）

把孤立结论连成可证伪的新判断。项目记忆库每期只增结论（F 条目），跨文献联系（C 条目）却长期停滞——这是已知薄弱环节。本技能专职补这一环：**扫候选 → 查新颖 → 自反驳 → 出预测**。

## 一、与谁分工（三者互补，不重叠）

| 角色 | 管什么 | 不管什么 |
|---|---|---|
| `self-audit` | 流程对不对（十六维评分、闭环健康、机制推理引擎健康、自审独立性） | 内容能不能生出新洞见 |
| `tools\memory.py` | 记忆库读写（ingest / search / check） | 洞见本身 |
| **本技能** | 内容综合——把结论连成新判断 | 流程评分、格式校验 |

一句话：self-audit 问「跑得对不对」，本技能问「这些结论合起来说明了什么」。

## 二、方法论根基：Swanson ABC 与两种发现模式

跨文献联系不是凭空联想。它的祖师爷是 **Swanson 的 ABC 模型**：A–B 有文献支持、B–C 有文献支持 → 推断 A–C 是新联系（传递推理）。由此分两种操作模式：

- **closed discovery（闭合发现）**：已知 A 与 C 两个领域，去找桥接它们的 B。适合「我已经怀疑这两条结论有关，帮我找中间环节」。
- **open discovery（开放发现）**：已知 A，从 B 领域里捞出**从没人提过**的 C。这才是「生成新假说」——对应本技能的 `insight_scan.py` 二跳桥接。

记忆库里每一条 F 就是一个「概念节点 + 断言」，`tools\insight_scan.py` 把 F 与其文本中的实体连成二部图，ABC 链就是在图上找路径。

### 两层图：提及层 + 类型层

v1 只用了**提及层**（结论文本里出现了哪些实体）——看到「两条都提到 STING」，却看不到「一条在降解它、另一条在让它沉默」。v2 加了一层**类型层**：每条 F 下方手写一行三元组

```
  - 三元组：(Omaveloxolone, INHIBITS, STING)；(STING, CAUSES, 衰老)
```

一条 F 可挂多条（机制链要拆开写，如 `GNAS→BCAA→NAD+→线粒体融合` 拆成 3 条）。三元组带来三样东西：

- **谓词带极性** → 沿路径做符号运算，给出连接的**方向**（促进 / 抑制 / 未知）
- **实体带 type** → 按 metapath 判因果链是否合理（分子→过程→表型 加分，工具/干预为端点降权）
- **同主客体、极性相反** → 直接判为**谓词冲突**，比标签对冲精确

谓词闭集（11 个；新增须同步 `insight_scan.py` 的 `PREDICATES`）：

| 谓词 | 极性 | 含义 | 谓词 | 极性 | 含义 |
|---|---|---|---|---|---|
| `ACTIVATES` | +1 | 激活/促进 | `TREATS` | +1 | 治疗/改善 |
| `INHIBITS` | −1 | 抑制/阻断 | `INDICATES` | 0 | 标志/诊断 |
| `CAUSES` | +1 | 导致/驱动 | `TARGETS` | 0 | 靶向 |
| `REGULATES` | 0 | 调控（方向未定） | `PART_OF` | 0 | 组成/属于 |
| `ASSOCIATED` | 0 | 关联 | `USED_FOR` | 0 | 用于 |
| `HOMOLOG` | 0 | 跨物种同源 | | | |

符号运算：`(+)·(+)→+`、`(−)·(−)→+`、`(+)·(−)→−`、含 `0` 则方向未知（联系仍成立）。
主体/客体必须能在 `tools\entities.json` 里解析（别名会自动归一，如 `RICTOR`→`mTOR通路`）；解析不了，脚本会在头部列「未入词典」告警。

## 二之二、物理介质桥接层（v3，2026-10-11 新增）

v2 能判方向、判冲突，但「两条结论有关」仍靠共享实体/共现，后果是产出 C004 这类「都碰线粒体→收敛」的浅联系——方向对、深度不够、替换成本为零。v3 加第三层：**物理介质桥接**，把联系从「主题词层」钉到「分子-物理层」。

三条铁律（介质层候选的额外硬门槛，违反即退回）：
1. **介质具体**：两篇现象落到**同一物理实体**（一种脂质 / 氧化还原对 / 接触位点 / 离子梯度），不是抽象词。
2. **旋钮正交**：两篇各动一个**正交旋钮**，最后作用到**同一执行器**；同轴则退化为共现。
3. **方向可测 + 自带证伪对照**：预测给得出方向，且有一条同时给「支持/反驳」两种归宿的对照。

介质词典、推理三步、验收样例（C004→C004★ 心磷脂桥接）与打分规则，见随技能目录存的 `media_bridge.md`。命中介质桥接的候选 score ×1.5（不可替换性更高）。介质桥接已由 `tools\reason_engine.py` 的 **R1** 脚本化（2026-10-11 P1，设计见同目录 `reason_engine.md`）——C004 回归测试通过；词典扩充与「落地」仍需人工把关。

**机制推理引擎（R1–R5，2026-10-11）**：`tools\reason_engine.py` 在 R1 之上补齐 R2 缺口（层级跳跃，找「本该有连接却没有」）、R3 张力（同主体反向分叉，找「缺失的条件变量」）、R4 瓶颈/冗余（跨文献链的中间节点，判「必经 = 干预靶点 / 有旁路 = 冗余」）、R5 跨层级同构（两跳链抽象成模式，同模式 + 实体不相交 → 跨系统迁移假说）。R1/R2/R3/R4 自动产出 **Q 问题库**提案（`findings.md`「三、问题」区，Q001–Q007），给「未知」一等公民：假说生成 = 用库里的 F 去回答 Q。候选须过各自闸门并经人工复核才落库。**生成-批判闭环**：候选（R1/R2/R4/R5）入库前自动过「自我反驳」环——反例（severity 2 高危）/ 边界条件 / 断链点（severity 1 需人工），裁决 高危/需人工/存活；「存活」只代表自动环没抓到把柄，仍须人工过新颖性查重。全量规范见 `reason_engine.md`。

## 三、六种链接形态（候选长什么样）

跨文献联系反复出现于六种可辨识结构。逐条拿结论库去套：

| # | 形态 | 判据 | 扫描类别 |
|---|---|---|---|
| 1 | **同靶点、多路径** | 两条 F 命中同一实体，机制描述不同 | A 直接共现 |
| 2 | **同逻辑、跨系统** | 两条 F 功能同构，作用对象不同物种/器官 | A 直接共现（跨物种） |
| 3 | **矛盾/张力** | 同一实体上效应相反，指向「条件依赖」 | **D 谓词冲突**（首选）/ C 标签对冲 |
| 4 | **上下游拼接** | A 的输出是 B 的输入，可串成机制链 | **B 二跳链**（带方向） |
| 5 | **趋势汇聚** | ≥3 条 F 独立支持同一方向，来源不同 | A 直接共现（多边） |
| 6 | **空白暴露** | A 与 B 各自成立，交界处无任何 F 覆盖 | B 二跳链（开放发现） |

## 四、打分排序：候选不是平铺的，是排过序的

借 **Open Targets 的乘式**（证据分 = 频率 × 强度 × 置信度）与 **DWPC 的度惩罚**（Himmelstein 等，惩罚经过高度数节点的路径），取其思想不取其重器。三类候选各有公式，`α = 1.0`，`c̄` = 两条结论置信度均值（高 3 / 中 2 / 低 1）：

```
A 直接共现：score = [ Σ_E 形态权重 / 度(E)^α ] × c̄
B 二跳链：  score = [ Σ_路径 PRED_W(p₁)·PRED_W(p₂)·metapath_bonus / 度(M)^α ] × c̄
D 谓词冲突：score = W_CONFLICT × c̄
```

- **形态权重（A）**：矛盾 2.0 ｜ 机制-干预接口 1.5 ｜ 同族共现 1.0
- **PRED_W（B）**：机制谓词高、弱谓词低——`ACTIVATES/INHIBITS/CAUSES` 1.0 ｜ `TREATS/TARGETS` 0.8 ｜ `REGULATES` 0.7 ｜ `HOMOLOG` 0.6 ｜ `INDICATES` 0.5 ｜ `ASSOCIATED` 0.4 ｜ `PART_OF/USED_FOR` 0.3
- **metapath_bonus（B）**：分子→过程/细胞→表型/疾病 = 1.5（像机制链）；工具/干预为端点 = 0.6（生物信号弱）；其余 1.0
- **度(E)**：该实体出现在多少条结论里。**度越高越被压低**——避免「因为都跟 p53 有关所以算联系」这种泛化废话。
- **W_CONFLICT**：谓词冲突固定 3.0（精准类别，压过所有共现候选）。

记忆库只有百来条，做不了 GNN/图谱补全，所以只取「度惩罚 + 乘式打分 + 符号运算」这几个可迁移内核，用标准库实现。

## 五、执行层：先跑 `insight_scan.py`，再动脑

```bash
python tools\insight_scan.py                       # 打印四类候选（默认每类前 12）
python tools\insight_scan.py --top 20 --min-degree 2
python tools\insight_scan.py --write learning\runs\insight_candidates.md
```

它输出四类候选（按精度递减排列）：
- **D 谓词冲突**：同一 `(主体, 客体)` 上极性相反（形态 3 的首选）
- **B 二跳链**：三元组串成 `s1 -p1→ M -p2→ o2`，即 open discovery，附**净方向**（形态 4/6）
- **A 直接共现**：两条结论共享实体（形态 1/2/3/5，召回用）
- **C 标签对冲**：同一实体上一条 `#干预`、另一条 `#安全信号`

已在库的 C 条目对应的配对会标 `[已覆盖]`，不重复提示。头部报「已标注三元组 N 条 / 共 M 条边」，并对未入词典的实体、越界谓词告警。

**候选 ≠ 结论**。脚本只负责把「值得看的配对」摆到眼前，成立与否由后两步判定。

### 标注维护（新结论入库后必做）

`memory.py ingest` 写进来的新 F **不带三元组**——脚本照常运行（提及层仍覆盖它），但要进类型层，需人工补一行：

```
  - 三元组：(主体, 谓词, 客体)；(主体, 谓词, 客体)
```

规则：主体/客体用规范名或词典别名；谓词只能取闭集 11 个；一条 F 的机制链拆成多条；`HOMOLOG` 专给跨物种同构。头部「已标注 N 条」长期低于结论总数，说明标注没跟上，审计时应补。

## 六、工作流程

1. **扫候选**：跑 `insight_scan.py`，得到排序后的候选配对。
2. **挑**：从每类高分候选里选值得深挖的。同一条 F 反复出现说明它是枢纽，优先看。
3. **验证（硬门槛）**：每条候选必须同时满足——
   - 挂 **≥2 条 F 编号**（只有 1 条 = 不是跨文献，直接弃）
   - 能说清 **「为什么这两条能连」**（共同实体 / 同构逻辑 / 因果接口 / 方向一致 / 交界空白）
4. **查新颖性（自动闸门）**：先跑 `python tools\novelty_gate.py --source all --days 90`——它把候选两侧概念拆成英文检索词，在 Europe PMC + Crossref 近 90 天窗口做**抢先核验**，按「双专有词」分档：**抢先**（两侧均命中专有词）→ 直接否决，降级为「已知」不入库；**疑似**（只命中泛化词）→ 人工看；**未抢先** → 可进后续（仅代表窗口内无覆盖，不等于绝对新颖）。这是观点文能否立住的命门，`paper-lookup` 留作窗口外/跨库的人工补查。
5. **自我反驳**：给候选写一段**证伪攻击**——找反例、找边界条件、找「什么情况下这条联系会崩」（借 PaperQA2 矛盾检测 + 多智能体辩论思想）。可先跑 `python tools\reason_engine.py --critique` 让生成-批判闭环自动摆出三类攻击材料（反例 / 边界条件 / 断链点），再人工判读。**写不出攻击点，说明还没想透，退回第 2 步**。
6. **出预测**：写一条可证伪预测（见第七节）。
7. **入库**：`python tools\memory.py add --type link --refs "F0xx F0yy" --pred "预测原文"`。联系写在 `findings.md` 的「二、联系」区，**禁止手改 ID**。
8. **校验**：`python tools\memory.py check`，确认 ID 连续、格式合规。

## 七、可证伪预测怎么写

预测是联系与「感想」的分水岭。合格的预测必须**具体、可检验、有方向**，能被后续实验或文献推翻。

- 合格：「若 X 是共同节点，则在敲低 X 的模型里，A 与 B 两条表型应同时消失；若只消失其一，则 X 非共同节点。」
- 合格：「若该逻辑跨物种成立，则在物种 C 中应能检出同源信号分子；检不出则联系不成立。」
- 不合格：「二者可能相关」「值得进一步研究」「有望成为靶点」——**不可证伪，一律退回**。

## 八、质量闸门（硬性，违反即拒）

- 只挂 1 条 F → 弃（不构成跨文献）
- 给不出可证伪预测 → 弃（是感想不是联系）
- 说不清连接理由 → 弃（凑数联想）
- 过不了新颖性查重（前人已提出）→ 不入库，标「已知」
- 过不了自我反驳（找不出任何攻击点）→ 退回重想
- 一期找不到真联系 → **如实报 0，不凑数**（宁缺毋滥）
- 预测必须指向「什么结果会推翻它」，否则不算预测

## 九、调用时机

- **每期报告生成后**：跑一次 `insight_scan.py`，把当期新结论与历史结论对撞
- **第 7 步审计**：检查 C 条目是否随期增长（长期零增长 = 本环节失效，需查原因）
- **用户要求**：从积累的结论里找新发现、问「这些结论合起来说明了什么」

## 十、纪律

- 结论（F）与联系（C）分区存放，互不混写
- 每条联系至少两个不同职能的证据源（呼应 AGENTS.md 第三节的交叉验证要求）
- 入库后必须跑 `memory.py check`，脚本报失败即回退修正
- 本技能只产出「可证伪的判断」，不产出「研究综述」——判据不够就留着，等下一期结论补齐
- 打分公式与脚本 `tools\insight_scan.py` 必须保持一致，改了公式就同步改两边
- 技能自身可进化：发现新的联系形态，追加到第三节的形态表并在此记录来源
- v3 来源（2026-10-11）：用户指出 v2 产出「浅共现」（C004 这类「都碰线粒体」的并置，替换成本为零），要求机制更强。回应是新增「二之二 物理介质桥接层」+ `media_bridge.md`，把联系下钻到「具体介质 × 正交旋钮 × 同一执行器 × 自带证伪对照」四要素。

## 十一、假说论文写作（产出端）

当用户要把 C 条目写成可投递的假说论文（Hypothesis / Perspective）时，调用随技能目录存的 `hypothesis_paper_format.md`：

- 五个必写章节（顺序固定）：Introduction → Hypothesis → Evaluation of the hypothesis → Future directions → Conclusions。
- 硬数字公约数：摘要非结构化 ≤250 字、正文 ~3000–4000 字、≥1 张核心机制图（理想 ~4）、≥30 条带 DOI 的文献、标题明示「假说」。
- 硬纪律：本文外推的介质/机制桥必须明标「尚未被直接测定」；引用用上标序号，禁内部草稿体（`[ref F051]`）；每条预测带证伪判据；DOI 不留空。

v4 来源（2026-10-11）：用户指出 C004 论文结构是我自创的、不符合任何目标平台规范，「卖点（心磷脂桥）写在 report 却没写进正文」，要求先看真实假说范文再改，且成品要「哪个平台都能收」。回应是新增本节 + `hypothesis_paper_format.md`，把假说论文体裁固化为通用规则。
